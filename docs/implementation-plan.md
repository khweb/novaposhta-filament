# Плагін «API Нова Пошта»: план реалізації

## Документація та результат

Перший крок реалізації — зберегти цей план і створити кореневий `AGENTS.md`. Узгоджені зміни вимог відображаються в плані. Під «агентами» мається на увазі файл правил: паралельні виконавці та окремі файли ролей не входять до завдання.

Самостійний Composer-пакет для Filament ^5.11, Livewire ^4.0, Laravel 12–13. Перед реалізацією потрібно перевірити останній стабільний Filament. Перша версія: локальні довідники доставки, налаштування, автоматичне й ручне оновлення, PHP API, публічний REST API та реактивна сторінка перевірки. Без ТТН, розрахунку вартості, відстеження та демонстраційного застосунку.

Навички: laravel-specialist, laravel-patterns, laravel-filament, laravel-filament-v5, olakunlevpn-filament-skills; [laravel-filament-v5-ui-ux](https://github.com/jotafurtado/dev-skills/tree/main/skills/laravel-filament-v5-ui-ux), [UI UX Pro Max](https://skills.sh/nextlevelbuilder/ui-ux-pro-max-skill/ui-ux-pro-max), офіційний [livewire-development v4](https://github.com/laravel/boost/blob/main/.ai/livewire/4/skill/livewire-development/SKILL.blade.php). Відсутні навички підключаються під час розробки й не стають залежностями користувачів пакета.

## Адаптер і зберігання

Дослідити офіційну документацію та [daaner/NovaPoshta](https://github.com/daaner/NovaPoshta). Реалізувати власний адаптер Laravel HTTP Client без обов’язкової залежності від стороннього SDK.

JSON-запити містять `modelName`, `calledMethod`, `methodProperties` і за потреби `apiKey`. Помилки HTTP та помилки всередині JSON обробляються окремо.

Методи: `getAreas`, `getCities`, `getSettlements`, `getWarehouses`, `getWarehouseTypes`; для вулиць — `searchSettlementStreets` з окремою нормалізацією вкладеної відповіді.

`CityRef` і `SettlementRef` зберігаються окремо з явним зіставленням. Для `getSettlements` початковий розмір сторінки — 150. Перевіряються повнота, повторення сторінок і недостовірний `totalCount`. Історичні обхідні рішення звіряються з актуальними відповідями та контрактними тестами.

Доступність довідників перевіряється окремо від чинності ключа. Для ключа — запит лише для читання `Counterparty/getCounterparties` із мінімальним лімітом; відомості контрагентів не зберігаються й не показуються.

### Префікс таблиць

`table_prefix` у `config/nova-poshta.php`, змінна `NOVA_POSHTA_TABLE_PREFIX`. Типове значення — `api_nova_poshta_`; дозволено `api_` із таблицями `api_areas`, `api_settlements`, `api_warehouses` тощо.

Єдиний механізм імен застосовується до моделей, міграцій, зв’язків, запитів і перевірок існування таблиць. Префікс з’єднання застосовується Laravel окремо. Імена індексів і обмежень мають бути короткими для підтримуваних СУБД.

Префікс задається до перших міграцій через конфігурацію, а не адміністративний інтерфейс. Його зміна не перейменовує таблиці; перенесення наявної БД потребує окремої міграції.

Власні таблиці: налаштування, покоління, області, райони, населені пункти, міста компанії та зіставлення, типи відділень, відділення/поштомати, кеш вулиць і журнал оновлень. Зберігаються зовнішні Ref, доступні назви, зв’язки, адреси, координати, графіки та обмеження доставки. Райони формуються з територіальних даних населених пунктів.

## Адміністративний інтерфейс і синхронізація

Після встановлення, міграцій і `NovaPoshtaPlugin::make()` доступний пункт «API Нова Пошта»: налаштування, довідники лише для читання, оновлення та перевірка.

Один зашифрований ключ на застосунок. Поле дозволяє замінити ключ; збережене значення не повертається у Livewire, журнали та HTTP. Доступ до сторінок і дій перевіряють серверні Gates, за замовчуванням доступ закритий. Приклад налаштування — у README.

Мови: uk, ru, en; локаль застосунку, резервна — uk. Стандартна тема Filament, видимі підписи, клавіатура, адаптивність, світлий і темний режими.

### Розклад

Кожні N годин, щодня, щотижня або щомісяця; час і часовий пояс. Відсутній день місяця замінюється останнім. Автооновлення спочатку вимкнене; запропоновано щодня о 03:00, Europe/Kyiv.

### Черга та публікація

- Спільне блокування ручного й автоматичного запуску.
- Посторінкова побудова нового покоління з обмеженими повторними спробами.
- Перевірка повноти та зв’язків, атомарне перемикання активного покоління.
- У разі помилки попередні дані залишаються доступними.
- Один пошук використовує одне покоління.
- Ручний запуск ігнорує розклад; повторне натискання показує активне завдання.
- Журнал містить етап, кількості записів, час, результат і безпечну помилку; heartbeat допомагає виявити зависання.
- Scheduler перевіряє розклад щохвилини; README описує cron і worker. Діагностика показує останні звернення та виконання.
- Вулиці завантажуються на запит, кешуються на 24 години; однакові одночасні запити об’єднуються.

## PHP API, REST і Livewire

Спільний сервіс пошуку використовується PHP-споживачами, REST-контролерами й сторінками Filament.

Публічні GET-маршрути під `/api/nova-poshta/v1`: `/areas`, `/districts`, `/settlements`, `/warehouses`, `/warehouse-types`, `/streets`.

Параметри: `q`, `page`, `per_page`, застосовні `area_ref`, `district_ref`, `settlement_ref`; для відділень — `type=branch|parcel_locker`. Вулиці потребують населеного пункту та щонайменше трьох символів.

Формат: `data`, `meta`, `links`, документовані поля та зовнішні Ref. Типово 20 записів, максимум 100; стабільне сортування.

Помилки: 422, 429, 503 `directory_not_ready` до першого завантаження та 503 за недоступності пошуку вулиць. Ліміт — 60 запитів/хв на IP; вулиці — додатково 10. Окремий спільний ліміт зовнішніх звернень.

REST можна вимкнути, змінити префікс і middleware. Публічного доступу до налаштувань і запуску оновлень немає.

### Сторінка перевірки

Livewire 4 та Filament Forms/Schemas:

- область → необов’язковий район → населений пункт → відділення/поштомат;
- очищення залежних значень після зміни батьківського поля та пояснення недоступності;
- пошук без перезавантаження з debounce 400 мс; застарілі відповіді не замінюють нові;
- видимі стани завантаження, порожнього результату та помилки; джерело даних, час відповіді й дата оновлення;
- явні перевірки підключення та ключа із захистом від повторного натискання;
- опитування прогресу раз на дві секунди лише під час активного завдання;
- кожна дія перевіряє права й вхідні дані; бізнес-логіка залишається в сервісах.

## Перевірка та постачання

Перевірити встановлення, меню, Gates, переклади й захист ключа; префікси за замовчуванням і api_ разом із префіксом з’єднання, зв’язки та rollback.

Контракти адаптера: форми відповідей, помилки, пагінація, недостовірний totalCount та адресні ідентифікатори.

Синхронізація: конкурентні запуски, повтори, переривання, зависання, перемикання поколінь і збереження попередніх даних. Розклад: часові пояси та граничні дати.

REST: фільтри, пагінація, поштомати, ліміти й кеш вулиць. Livewire та браузер: залежні поля, скидання вибору, права, помилки, реактивність, клавіатура й адаптивність.

Автоматичні тести використовують HTTP fixtures. Реальна перевірка з ключем користувача виконується окремо. Сумісність: SQLite/MySQL/PostgreSQL та Laravel 12/13.

README містить встановлення, префікс БД, права, scheduler/worker, PHP-приклади, REST-контракт і джерела дослідження.

## Уточнення реалізації за перевіреними відповідями API

### Реальна синхронізація відділень на локальному стенді (29.10.2026)

- На запит користувача перевіряється повне завантаження відділень із реального API замість завжди активних HTTP fixtures. Ключ, збережений у стандартному browser-стенді, та наявні дані зберігаються.
- Звичайний loopback-стенд використовує реальний HTTP, постійну SQLite-базу, асинхронну database queue та спільний файловий кеш. Окремий CLI worker обробляє сторінки й щохвилини перевіряє розклад; закриття сторінки не перериває завдання. Fixtures вмикаються лише явним заголовком сценарію й ізольовані іншими базами.
- Виправлено відновлення втраченої початкової доставки queued-запуску; наступні кроки відновлюються за збереженою ревізією. Відновлення не продовжує граничний строк очікування першого worker. Додано регресійні перевірки без дублювання запуску та з обмеженням очікування.
- Збережено версійне повне завантаження, контрольні точки та атомарну публікацію після перевірки повноти/зв'язків. Інкрементальний контракт API не підтверджено. Дослідження й експлуатаційні команди — у `docs/warehouse-sync.md`, фактичні результати — у `docs/verification.md`.
- На реальному відділенні №400 у Києві виявлено, що `PostMachineType=FullDayService` не означає поштомат. Класифікація спирається на `CategoryOfWarehouse=Postomat` або налаштовані Ref типів, включно з типом поштоматів ПриватБанку. Ознака режиму обслуговування більше не змінює тип відділення.
- Функціональний орієнтир користувача — модуль OpenCart із пошуком міста та підбором відділення. Поточний етап охоплює реальний довідник відділень/поштоматів і його залежності; ТТН, тарифи та відстеження залишаються окремими етапами.

### Візуальне доопрацювання налаштувань (29.10.2026)

- На `/admin/nova-poshta/settings` підключення та розклад розташовані послідовно на всю доступну після навігації ширину; вузьких паралельних секцій немає. Використовуються стандартні компактні секції Filament із поясненнями й іконками.
- Стан ключа показується коротким бейджем із текстом та іконкою; дата перевірки й поле заміни відокремлені візуально. Збережений ключ не передається у форму.
- Перемикач автоматичного оновлення має власне пояснення. Періодичність і відповідний параметр розташовані поруч: інтервал годин, час, день тижня або день місяця. Часовий пояс займає повний рядок для погодинного й щоденного режиму, а для щотижневого й щомісячного — рядок разом із часом. На мобільному всі поля йдуть в одну колонку. Єдина дія «Зберегти налаштування» має висоту 44 px і завершує форму.
- Зберігаються тема Filament, серверна валідація, Gates та бізнес-логіка. Нові тексти локалізовані українською, російською й англійською.

### Навігація та вигляд довідників (29.10.2026)

- У головному меню залишається один пункт «API Нова Пошта». Штатний Cluster переносить «Налаштування», «Довідники», «Оновлення» та «Перевірка» у другий рівень навігації на кожній сторінці пакета. Доступні пункти визначаються Gates; звіт виділяє розділ «Оновлення». Наявні URL і назви маршрутів збережено.
- Після перенесення навігації налаштування, огляд оновлень, перевірка та звіт використовують компактні секції. Перевірка використовує всю ширину контенту без додаткової бічної колонки; пошук вулиці й корисні посилання можна розгорнути за потреби. Стандартна тема, видимі підписи та мобільне меню Filament збережені.
- Локальна копія UI UX Pro Max містить лише `SKILL.md`, без `scripts/search.py` і `references/pro-rules.md`; додаткових копій у доступних каталогах навичок не знайдено. Застосовано загальні правила навички, доступні композиції `form-layout.md` і `table.md`, офіційну документацію та вихідний код Filament 5.11; відсутній `panel-shell.md` не вважається перевіреним джерелом композиції.

- На `/admin/nova-poshta/directories` п’ять довідників вкладені під «Довідники» у ліву внутрішню навігацію. Біля кожного показано загальну кількість записів, а над таблицею — загальну й знайдену кількість. Верхній рядок перемикачів прибрано.
- П’ять локальних довідників мають окремі посилання через параметр `directory`. Заголовок та активний пункт відповідають вибору. Вулиці залишаються пошуком на запит, недопустимі значення відхиляються.
- Рядок — одна змістовна колонка на штатному Stack Filament: назва, батьківська ієрархія та видимий Ref. Райони показують область; населені пункти — область і район; відділення/поштомати — область, район, населений пункт, тип відділення й текстову категорію. Області й типи відділень не мають штучних батьків.
- Для районів доступний фільтр області; для населених пунктів — області й району; для відділень — області, району, населеного пункту, типу відділення та категорії. Варіанти мають пошук, обмеження 50 записів і підписи з ієрархією та Ref. Зміна області очищає район і населений пункт, зміна району — населений пункт. Є штатні індикатори та скидання.
- Сортування користувачем вимкнено у всіх п’яти довідниках; стабільний порядок за назвою та Ref залишається в сервісі. У типах відділень також прибрано пошук. В інших довідниках пошук і пагінація збережені.
- У кожній із п’яти таблиць є швидкий перегляд: натискання рядка або кнопки «Переглянути» відкриває штатне модальне вікно ViewAction з копійованим Ref та батьками. Для відділень додано доступні адресу, координати й додатні обмеження ваги; графік роботи з локалізованими днями — у згорнутій секції. Сирий payload не показується; усі дії перевіряють Gate перегляду.
- `DirectoryBrowser` готує батьківські назви підзапитами без запитів на кожен рядок. Записи, батьки, лічильники й варіанти фільтрів належать до одного зафіксованого покоління; відсутня назва батька замінюється його Ref.
- Мобільний шаблон Filament 5.11 помилково використовує URL батька для дочірніх пунктів. Лише для піднавігації пакета підключено мінімальний виправлений шаблон зі штатних dropdown/button-компонентів: адреса, бейдж і поточний стан беруться з дочірнього пункту.
- Порожній результат відрізняється від відсутності завантажених даних. Нові пояснення перекладені uk/ru/en; права доступу та сервіси пошуку не змінюються.

### Візуальне доопрацювання сторінки оновлень (29.10.2026)

- На `/admin/nova-poshta/updates` запуск винесено в шапку сторінки. За наявності активного завдання кнопка пропонує відкрити його через чинний захищений сервіс запуску.
- Верхня секція показує останню успішну публікацію, поточне завдання та стан автоматичного оновлення. Часові позначки scheduler/worker/API згруповані у згорнутій діагностиці.
- Історія має власний заголовок, текстові статуси з іконками, зрозумілі дати та доступ до повного звіту. Вибір відображуваних стовпців вимкнено, щоб прибрати кнопку вибору й порожню панель над таблицею. Технічні подробиці доступні у звіті; на мобільному залишаються дата, результат і звіт. Помилки та попередження ключа відображаються біля результату.
- Збережено Gates, сервіс запуску, опитування лише під час активного завдання, семиденну історію та стандартну тему Filament. Нові тексти локалізовано uk/ru/en.

### Візуальне доопрацювання перевірки адреси (29.10.2026)

- На `/admin/nova-poshta/tester` область, необов’язковий район, населений пункт, тип і відділення зібрано в одну секцію на всю доступну після навігації ширину. Область і район ділять рядок; населений пункт має повну ширину, тип займає третину рядка доставки, відділення — дві третини. На мобільному всі поля послідовно розташовані в одну колонку.

### Візуальне доопрацювання звіту (29.10.2026)

- На `/admin/nova-poshta/report/{runId}` заголовок містить номер запуску. Прогрес має текстовий статус з іконкою, окремі позначки сторінки й кількості записів; помилки, очікування та результат публікації показуються штатними Callout-компонентами Filament.
- Лічильники запитів, помилок, повторів і попереджень відокремлені від відомостей про запуск. Кількості за довідниками згруповані у згорнутій секції.
- Журнал використовує компактні рядки з роздільниками: основне повідомлення контрастне, час та етап — дрібнішим сірим текстом. Інформаційні події не дублюють однаковий бейдж, помилки та попередження мають текстові позначки. Технічні подробиці розкриваються дією «Деталі» з доступною назвою та видимим фокусом.
- Прогресбар збільшено до щонайменше 88 px; всередині показуються поточний етап, сторінка API та кількість записів. Заповнення відображає завершені етапи, а не вигаданий відсоток записів; 100% з’являється лише після публікації. Збережено нативну семантику progress і текстове пояснення для допоміжних технологій.
- Стилі ізольовані сторінкою звіту, використовують токени Filament для світлої й темної тем без збірки frontend. Збережено курсорну навігацію по 50 подій, паузу автопрокручування, Gates та опитування активного запуску раз на 2 секунди.
- Зміни стосуються представлення звіту; нові тексти перекладено uk/ru/en, сервіси синхронізації не змінюються.

### Узгоджене розширення спостережуваності (29.10.2026)

- Компактна історія за останні 7 днів. Натискання відкриває окрему сторінку звіту: стан, етапи, кількість записів, тривалість, помилки, повтори та повний посторінковий журнал зрозумілою мовою. Без експорту, email чи Telegram.
- Живий звіт опитується кожні 2 секунди під час роботи. Невідомий обсяг API не перетворюється на вигаданий відсоток; 100% означає перевірку й атомарну публікацію. Закриття браузера не перериває чергу.
- Короткі ідемпотентні завдання по сторінках зі збереженими контрольними точками. Тимчасові помилки повторюються з обмеженням і затримкою; остаточний збій потребує нового повного запуску. Попередні довідники залишаються доступними.
- Структуровані події містять лише дозволені метадані, без ключа, сирих відповідей або даних контрагентів. Очистка журналу не видаляє активні запуски, довідники чи дату останньої успішної публікації.
- Стан ключа перевіряється після заміни й на початку запуску. Відхилений ключ відрізняється від недоступності перевірки; попередження показується біля запису синхронізації. Публічні довідники завантажуються незалежно від ключа.
- Зміни схеми — окремою міграцією для встановлених пакетів; перевіряються префікси, rollback, черга, збої, повторна доставка, права, локалізація та Livewire.
