# Участь у розробці

Дякуємо за допомогу в розвитку пакета. Основна мова документації, issues і pull requests — українська.

## Підготовка

Потрібні PHP ^8.3 та Composer.

```shell
composer install
composer test
composer lint
```

Тести запускаються через Orchestra Testbench; окремий Laravel-застосунок не потрібний. Типова база — SQLite у пам’яті. Тестові HTTP-запити підмінено fixtures.

## Внесення змін

1. Створіть окрему гілку для зміни.
2. Опишіть проблему або нову поведінку, яку вона вирішує.
3. Для зміни бізнес-логіки додайте відповідний регресійний тест.
4. Оновіть документацію, якщо змінюється встановлення, конфігурація чи API.
5. Виконайте перевірки, що стосуються зміни, та відкрийте pull request.

Перед зміною коду ознайомтеся з [AGENTS.md](AGENTS.md) і [планом реалізації](docs/implementation-plan.md).

## Вимоги до коду

- Зберігайте сумісність із Laravel 12/13, Filament ^5.11 і Livewire ^4.0.
- Бізнес-логіку розміщуйте в сервісах; REST і Filament використовують спільний пошук.
- Усі імена таблиць формуйте через `Support\Tables`; префікс з’єднання застосовує Laravel.
- Для адміністративних дій перевіряйте Gates на сервері.
- Збережений API-ключ не повинен потрапляти в Livewire, HTTP-відповіді або журнали.
- Для нових текстів інтерфейсу додавайте переклади `uk`, `ru` та `en`.
- Використовуйте стандартні компоненти й тему Filament.

## Перевірки

```shell
composer test
composer lint
composer validate --strict
```

Для автоматичного форматування:

```shell
composer format
```

CI містить матрицю Laravel 12/13, PHP 8.3/8.4 та SQLite/MySQL/PostgreSQL. Локальний прогін на іншій СУБД використовуйте лише з окремою базою `nova_poshta_test*`: тестовий bootstrap очищає її.

Зміни лише в документації перевіряйте на коректність посилань, прикладів і відповідність поточній реалізації.

## HTTP fixtures та реальний API

Під час автоматичних тестів не використовуйте реальні API-ключі й дані контрагентів. Справочні зразки містяться в `tests/Fixtures`. Реальні перевірки виконуйте окремо та вказуйте їхній обсяг у pull request.

## Повідомлення про помилки

Вкажіть версії PHP, Laravel, Filament, Livewire та СУБД, кроки відтворення, очікуваний і фактичний результат. Використовуйте безпечні коди помилок із журналу пакета.

Про вразливості повідомляйте відповідно до [SECURITY.md](SECURITY.md).
